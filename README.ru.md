# Local RP (LRP)

[English](README.md) · [Українська](README.uk.md) · [Русский](README.ru.md)

Self-hosted веб-приложение для ролевых диалогов с ИИ-персонажами: каталог персонажей, чат со стримингом ответов в реальном времени и ветвлением диалога, редактор и генератор персонажей, API-ключи с ограниченными правами, админская часть и зона владельца с зашифрованными бэкапами.

> **Это репозиторий-витрина: в нём только скриншоты и обзор проекта.**
> Исходный код лежит в приватном репозитории. С удовольствием покажу его на созвоне или дам ревьюеру доступ на чтение по запросу.

![Каталог персонажей](docs/screenshots/02-catalog.png)

![Ответ, который стримится в браузер](docs/streaming.gif)

*Ответ, который стримится в браузер через Server-Sent Events. В этом демо-окружении модель — небольшая локальная модель через Ollama; в обычной настройке backend обращается к OpenRouter-совместимому API.*

> Интерфейс пока **только на русском** (локализация в планах). Примеры персонажей и диалогов на скриншотах на английском.

📖 **[Справочник настроек](docs/SETTINGS.ru.md)**: все настройки по категориям, каждая со скриншотом (раскрывающиеся списки).

## Основное

**Персонажи**
- Каталог с карточками и аватарами, тегами, поиском по тексту и фильтрами по тегам (включить / исключить, AND / OR)
- Профиль и редактор персонажа: приветствие, персона (системный промпт), теги, загрузка изображения, переключатели «приватный промпт» и «опубликован»
- Форма генератора персонажей с автосохранением черновиков (режимы «персонаж» и «мир / RPG»)

**Чат**
- Ответы стримятся токен за токеном (SSE); ответ можно остановить в любой момент
- Свайпы (альтернативные ответы), редактирование, повторная генерация и **дерево веток диалога**
- Модель и «Author's Note» отдельно для каждого чата; **просмотр контекста модели**, показывающий, что именно уходит модели (персонаж, активные пресеты промптов, сообщения, примерное число токенов)
- **Команды чата:** `/cmd` — одноразовая директива режиссёра для модели, `/desc` — запрос к рассказчику на описание сцены; список команд открывается, когда сообщение начинается с `/`
- Фоновая генерация (опционально): если соединение оборвалось, ответ дописывается на сервере, а клиент снова подключается к нему

**Аккаунты и API**
- Регистрация только по инвайтам, роли (user / admin / root), смена пароля, список устройств с удалённым выходом
- Личные API-ключи с ограниченными правами (только чтение, создатель персонажей, полный или произвольный набор) и необязательным сроком действия
- Документация API генерируется из кода и открывается только владельцу API-ключа

**Админская часть**
- Пользователи и роли, инвайт-коды, LLM-модели (по умолчанию, порядок, включение), редактируемый справочник тегов (создание, переименование, объединение, порядок) и настройки сайта (вход, регистрация, обслуживание)

**Зона владельца (только root)**
- Управление секретами (ключи заменяются, назад не показываются)
- Зашифрованные **бэкапы** по расписанию (шифрование публичным ключом age, локальная папка и / или S3-совместимое хранилище, правила хранения с жёстким лимитом места, проверка каждого бэкапа во временной базе, необязательные уведомления в Telegram) и **восстановление**
- **Первый запуск:** одноразовый код настройки из журнала сервера, создание владельца и мастер настройки из шести шагов

**Интерфейс**
- Адаптивная вёрстка с отдельной мобильной навигацией
- Каждую настройку можно хранить в браузере или на сервере

## Технологии

| Часть | Технологии |
|---|---|
| Backend | Java 21, Spring Boot 3, Spring Security (JWT, API-ключи), Spring Data JPA / Hibernate, PostgreSQL, Flyway, Redis, Server-Sent Events, OpenAPI |
| Frontend | React 19, TypeScript, Vite, TanStack Query, Zustand, React Router |
| Инфраструктура | Docker, Docker Compose, nginx как входной gateway |
| Доступ к LLM | OpenRouter-совместимый chat completions API (со стримингом) |

## Архитектура

```mermaid
flowchart LR
    Browser["Браузер (React SPA)"] -->|HTTP| Gateway["nginx gateway"]
    Gateway -->|статические файлы| Browser
    Gateway -->|/api| Backend["Spring Boot backend"]
    Backend --> PG[("PostgreSQL")]
    Backend --> Redis[("Redis")]
    Backend -->|"chat completions (stream)"| LLM["LLM-провайдер"]
    Backend -. "SSE: token / done / error / cancelled" .-> Browser
```

- **Модульный монолит, package by feature.** Backend разделён на модули по возможностям (auth, user, character, chat, draft, invite, media, model, API-ключи, настройки сайта, секреты, бэкапы и другие).
- **Гексагональные слои внутри каждого модуля:** `domain` (сущности и правила), `application` (use case-ы и порты), `infrastructure` (адаптеры REST, базы данных, LLM, Redis). ArchUnit-тесты проверяют, что слои и модули зависят друг от друга только в разрешённых направлениях.
- **Изменения базы данных** версионируются миграциями Flyway.
- **Стриминг:** backend просит у LLM-провайдера ответ потоком и пересылает его клиенту как SSE-события (`token`, `done`, `error`, `cancelled`). В чате одновременно может идти только одна генерация; клиент может остановить её или заново подключиться к активной после разрыва.

## Тестирование

- Backend: JUnit 5, Mockito, Testcontainers (PostgreSQL), MockMvc, архитектурные тесты ArchUnit. **Покрытие backend тестами частичное.**
- Frontend: Vitest.
